Nexora Logistics — Admin Manual

Everything you can do from the admin, in plain English. Every page, every button, every form, every message. If something feels unclear, it's a bug in this manual — tell the developer.

Overview

The Nexora Logistics admin has 5 top-level sections: Dashboard Shipments People Content Settings. Everything you do belongs to exactly one of them. Nothing is hidden.

Rule of thumb: if it moves goods, it's in Shipments. If it involves a customer, it's in People. If it's a word the public sees, it's in Content. If it's a partner or a system check, it's in Settings.

Logging in

Go to /admin/login.php. Enter the admin email and password you were given. Sessions last until you tap Logout or close the browser.

Never share the admin URL with customers. The public site shows a discreet Staff link in the footer — that is the only public hint the admin exists. Customers do not otherwise see any admin link.

The dashboard

Four big tiles — one per top-level section (Shipments, People, Content, Settings) — plus a scroll-down reference of "How each page works" that lists every sub-page and its purpose.

TileWhat it does
📦 ShipmentsCreate, manage, monitor and control every shipment.
👥 PeopleTrack who looked at what, and manage the customer reviews on the homepage.
📝 ContentEdit every word your customers see on the public site and on the tracking page.
⚙️ SettingsPartner carriers and system diagnostics.
Live counters on the public homepage update from real data every few seconds. They never stop counting — so the site always looks alive.

Creating a shipment

From the dashboard tap Shipments → Create a Shipment. Or go directly to /admin/shipments.php.

Managing shipments

Shipments → Manage All — a searchable list of every shipment you've created.

  • Search bar — type any part of the tracking number, customer name, email, or city.
  • Status filter — narrow to in-transit, held, delivered, etc.
  • Each row shows — tracking number (tap to open shipment control), customer, origin → destination, transport, status, last update, carrier chip if assigned.
  • Actions column — Controls opens the tracking dashboard, Track opens the customer view.

Tracking Operations

Shipments → Tracking Operations — a single screen to see every active shipment's status and run the day-to-day controls (start, pause, resume) without opening each shipment.

Use this when you're managing many shipments at once and want to see who's moving, who's stuck, and who needs attention.

Fleet View

Shipments → Fleet View — every active shipment as a marker on one live world map.

  • Coloured markers — gold = moving, red = flagged (on hold / seized / delayed), green = delivered.
  • Search box — filter to a single tracking number, customer, city, or carrier.
  • Status dropdown — show only in-transit, only held, etc.
  • Tap any marker — a popup with the full details, plus buttons for Open, Route, and Public view.
  • Refresh button — reload the map with the latest data.
When to use Fleet View: you've just launched 5 new shipments and want to see all of them on one screen. Or a customer calls asking about their package — search their tracking number and jump straight in.

Shipment Control — the main workspace

This is where you actually run a shipment. Six tabs, each with a clear job.

Summary tab

The at-a-glance view: current status, speed, distance travelled / remaining, ETA, customer, transport, vehicle, last update. Any change you make in another tab updates this.

Live Map tab

  • Real live vector map (MapLibre GL JS + OpenFreeMap, no API key) with the shipment's position, the origin flag pin, the destination flag pin, and all waypoints.
  • The route line is colour-coded per leg — gold for air, blue for sea, grey for road, pink for bike, dark for pedestrian.
  • Tap the vehicle marker to see a popup with status, speed, last update.
  • ⛶ Fullscreen — bottom-right of the map.
  • The whole view is the same as the customer sees, so what you check here is exactly what your customer sees.

Movement tab

  • Speed (km/h) — how fast the tracking engine moves the shipment.
  • Tracking Mode — Simulation (typical) or a real feed if connected.
  • Start / Pause / Resume buttons — start moves the shipment forward, pause freezes it.
  • Save Movement Settings — applies the speed + mode to the tracking engine.
  • Current Position — manual lat/lng override. Type new values and tap Save Position to teleport the marker (useful for correcting a jump or setting a manual fix).
Speed rules: speed must be ≥ 0. A shipment in transit must have speed > 0. Don't exceed 2,000 km/h — the validator will refuse.

History tab (Tracking Timeline)

Every event the shipment has ever had — created, departed, cleared customs, held, released, delivered. Shows the 5 most recent. Tap Show all (N more) to see the rest. The wording here is what the customer sees. To change the wording, go to Content → Customer Messages.

Issues tab (Holds & Incidents)

Where you record anything that stops, delays, or flags the shipment.

  • Current issues at the top — each active hold with a Clear hold button. If more than 2, they collapse behind a "Show all" button.
  • Report something new — pick what happened from the dropdown:
    • Hold the shipment — Customs inspection, Security screening, Seized by authority, Compliance issue
    • Delay / operational — Weather delay, Vehicle breakdown, Damaged packaging, Port congestion
    • Progress — Out for delivery, Delivered
    • Release — Clear all active holds
  • Delay amount (optional) — type a number, pick Minutes / Hours / Days / Weeks / Months. This extends the ETA automatically.
  • Note shown to the customer — a short message. Example: "Awaiting customs clearance".
  • Record incident — saves everything and pushes the shipment to the correct status.
  • 📷 Attach photos / videos — opens an inline uploader right there. Useful for customs evidence, damage photos, proof of delivery.

Media tab (Photos & Videos)

All media attached to this shipment, in the order you uploaded it. Tap any photo to open it in a lightbox. Each item has a caption field, a Public / Private toggle (only Public items are seen by the customer), and a Delete button.

How to use the editor

  1. Tap + Add a stop
  2. Tap on the map where the stop is — lat/lng fields fill automatically
  3. Enter the name, type, and the leg type that arrives at this stop
  4. Tap Save & add another to add the next stop without reloading
  5. When all stops are in, tap 🛠 Rebuild route line — the map now shows each leg in its own colour
  6. The customer sees the same multi-coloured route on the public tracking page

People → Tracking Lookups

Every time a customer types a tracking number into the public site, they have to fill in a small form first: their name, email, and phone number. Those details are saved here. You do not need to chase the customer for contact info — they gave it up front.

Why this matters in real life

Imagine you're shipping to 40 different customers this week. One of them calls your office angry because their parcel is 3 days late. You don't have their phone number on file from the shipment, but you did get it when they last checked tracking. You open People → Tracking Lookups, search their name, and the number is right there.

What you can do here

  • Search by any word in the tracking number, name, email, or phone.
  • Tap View on a row to see the full record: IP address, device info, and a list of every shipment this same email has ever tracked.
  • Export CSV — downloads the whole list. Open it in Google Sheets or Excel. Useful for building a mailing list or sending a batch update email.

Real scenario

A customer emails you: "Where is my parcel?" but doesn't give a tracking number.

  1. Open Tracking Lookups
  2. Search their email address
  3. The list shows every shipment that email has looked up
  4. Tap the shipment row → opens the tracking control for it
  5. You answer with the exact status — no back-and-forth

People → Testimonials

The reviews shown on the public homepage in the sliding carousel. You choose which ones are public. You write them (from real customer quotes you received by email, WhatsApp, or in person), add a photo, and pick the star rating.

Adding a testimonial — step by step

  1. Tap People → Testimonials
  2. Fill in:
    • Author name — "Sarah Chen" (no fake names — use real people or clear company names)
    • Country — "Singapore"
    • Role — "Operations Manager, Meridian Imports"
    • Rating — 1 to 5 stars
    • Photo — either a URL or upload from your phone (≤ 512 KB)
    • Review text — the actual quote
    • Sort order — lower numbers show first
    • Published — tick to make it live
  3. Tap Add testimonial
Legal note: only publish testimonials you have permission to publish. Using a customer's name and photo without consent can get you in trouble. If in doubt, use just a first name and no photo.

Content → Site Content

Every word the public sees on the homepage, grouped by section: Hero, Services, Numbers, Contact, Footer.

Why this is powerful

If you want to change the headline from "Ship Worldwide with Nexora Logistics" to "Ship Faster with Nexora Logistics", you don't need the developer. Open Site Content, find the field, edit it, save. The homepage updates on the next page load.

Content → Customer Messages

Whenever something happens to a shipment — customs hold, weather delay, out for delivery, delivered — the customer sees a short message on the tracking page. Those messages are written here, in your own words.

How the system works

When you record an incident, the system looks up its admin key (for example customs inspection) and shows the matching customer message. Change the message here → the customer sees the new wording on their next page load.

Real example — softening a scary customs message

Default wording: "Your shipment is being inspected by customs authorities."

You want a less scary version. Open Customer Messages, find the row customs inspection, edit the description to:

"We're working with customs to complete a routine check. Your shipment is safe and we'll update you as soon as it clears."

Save. Every customer whose shipment is in customs now sees that message — without any code change.

Transport popups

The same idea but for map popups. Tap on a plane marker → you see the message defined here for air. Tap a ship → the message for sea. Change these if you want to sound less formal, or add extra context like typical travel times.

Settings → Carriers

Companies you partner with to move goods. Real examples: DHL, FedEx, a local freight forwarder, your own courier team.

When to add a carrier

  • You hand a shipment to a partner airline or shipping line
  • A local courier handles the last mile
  • You want the customer to see "Handled by DHL" on their tracking page
  • You want a small carrier chip next to the tracking number in the admin list

Adding one

  1. Name — "Nexora Express"
  2. Code — short, 2–4 letters. "NEX"
  3. Contact email / phone — optional, for your records
  4. Tracking URL — link to the carrier's own tracking page. Use {tracking} where the number goes. Example: https://www.dhl.com/track?awb={tracking}
  5. Logo — either paste a URL or upload from your phone (≤ 512 KB, PNG/JPG/WEBP/SVG)
  6. Active — tick to enable. Untick to hide from the shipment dropdown without deleting

Assign a carrier to a shipment

  1. Create a new shipment (or edit an existing one)
  2. Scroll to Carrier / partner
  3. Pick from the dropdown
  4. Save — the carrier chip appears next to the tracking number

Settings → System Diagnostics

Only needed if something looks broken. Shows whether the session system is running, the database is reachable, and PHP is healthy. If a page acts strangely, open Diagnostics first — it tells you if the problem is on the server side.

Full worked example — Singapore → New York City

This is the whole life of one shipment, from the moment you decide to move it to the moment the customer signs for it. Follow along and you'll know how to run any shipment afterwards.

Scenario

  • A customer in New York City (Brooklyn) ordered a crate of specialty tea from Singapore
  • Weight: 18 kg · Dimensions: 60 × 40 × 40 cm
  • Promised delivery window: 14 calendar days
  • Agreed service: standard air freight with last-mile by courier

Tap Create Shipment. The shipment exists. Status is Pending.

Note: NYC longitude is negative (-74.0060) because it's west of Greenwich. Singapore longitude is positive. If you enter NYC as +74, the map will draw it somewhere in Asia and every customer will see the wrong route.

Step 2 — Build the multi-modal route

Real journeys have many stops. This shipment has 6 stops — one each for pickup, airport, arrival, distribution, courier, and doorstep.

Open the shipment → Summary tab → tap Edit route. Now add the stops in order:

When all 6 are in, tap 🛠 Rebuild route line. The map now shows a gold air arc from Singapore to JFK, then grey and purple land legs in New York.

Optional but nice: add a 7th stop right before the doorstep, type ped, so the customer sees the courier walk the last few metres. It looks real on the map.

Step 3 — Start the journey

Open the Movement tab:

  • Speed → 850 km/h (typical long-haul cruise; the engine scales this to real wall-clock time so the shipment progresses naturally)
  • Tracking mode → Simulation
  • Tap Save Movement Settings
  • Tap ▶ Start Tracking

The vehicle marker starts moving. Customer can already open the public tracking page and see the plane crossing the Pacific.

Step 4 — Picked up and trucked to Changi

Customer-facing timeline gets events as the shipment moves. You can help the story along by recording events. Open the Issues tab and choose from the dropdown:

  • Out for delivery → customise the note to "Collected from Singapore warehouse"

Actually the cleanest way to describe a specific milestone is to use the Operational Event form on the Movement tab:

  • Event type → Picked Up
  • Location → Singapore Tuas Warehouse
  • Latitude → 1.2942
  • Longitude → 103.6376
  • Description → Shipment collected and sealed. Departing for Changi Airport.
  • Tap Record Operational Event

Step 5 — Arrives at Changi, boards the plane

Record another event:

  • Event type → Departed
  • Location → Singapore Changi Airport
  • Latitude → 1.3644
  • Longitude → 103.9915
  • Description → Loaded on flight SQ-026 to New York JFK.

Step 6 — Something goes wrong: Hong Kong airspace closure

Three days in, a typhoon closes the original routing. The flight has to reroute via Tokyo, adding 2 days. Here's exactly what to do:

  1. Open the shipment's Issues tab
  2. Under Report something new, choose Weather delay
  3. Delay amount → 2, unit → Days
  4. Note shown to customer → "Typhoon rerouting. Arrival pushed by 2 days. Our apologies."
  5. Tap Record incident

The system now:

  • Extends the ETA by 2 days automatically
  • Adds an event to the timeline
  • Shows the customer message you wrote
  • Keeps the shipment moving (weather delays don't pause it)
Delay vs hold: a weather delay is an operational hiccup — the shipment keeps moving, just slower. A customs hold stops movement. Choose the right one.

Step 7 — Lands at JFK

Record the arrival:

  • Event type → Arrived
  • Location → New York JFK International Airport
  • Latitude → 40.6413
  • Longitude → -73.7781
  • Description → Cleared US customs. Handed to local ground team.

Step 8 — US customs wants a look

JFK customs selects the crate for inspection. The shipment is now on hold.

  1. Open Issues tab
  2. Choose Customs inspection
  3. Delay amount → leave at 0 for now (you don't know how long it will take)
  4. Note shown to customer → "Your shipment is being inspected by US customs. We'll notify you the moment it clears."
  5. Tap Record incident

The system now:

  • Puts a mandatory hold on the shipment — movement stops
  • Changes the visible status to On hold
  • Red pulsing marker on the admin and public maps
  • Timeline shows "Customs inspection in progress" with your customer note
  • Blocks the Start / Resume buttons until the hold is cleared

Meanwhile, upload the customs form photo as evidence:

  • Tap 📷 Attach photos / videos (right under Record incident)
  • Pick the photo of the customs form from your phone
  • Context → Customs documentation
  • Tap Upload

Step 9 — Customs clears it

Two days later, US customs releases the crate.

  1. Open Issues tab
  2. Find the active hold at the top — "Customs inspection in progress"
  3. Type the clearance note → "Released by CBP officer badge 44921. Form CBP-7513 signed."
  4. Tap Clear hold

The shipment returns to In transit. Now tap ▶ Resume on the Movement tab to restart the engine. Movement continues toward Brooklyn.

Step 10 — Last mile in Brooklyn

Now it's genuinely close. Update the status by recording events:

  • Event → Departed from JFK area to Brooklyn Depot
  • Event → At depot, out for delivery when the van collects it
  • Event → Out for delivery when the courier bike takes it

Each one uses the dropdown and a short note. The customer's timeline fills up with clear, plain-English milestones.

Step 11 — Editing what the customer sees (advanced)

Suppose halfway through, a customer emails to say: "Stop calling it 'Port congestion'. It doesn't make sense for air freight."

Open Content → Customer Messages. Find the row with admin key port congestion. Change the description from the default to:

"Your shipment is being routed through a busy hub. We're monitoring for the fastest path."

Save. Every customer whose shipment hits a port-congestion event now sees that message instead.

Same idea for any message in the list — customs, weather, delayed, delivered — you can rewrite any of them.

Step 12 — Delivery

Courier arrives, customer signs. Record the final event:

  • Event type → Delivered
  • Location → Customer doorstep, Park Slope
  • Description → Handed to Michael Chen. Signed for.

Then upload the proof-of-delivery photo:

  • Issues tab → 📷 Attach photos / videos
  • Take a photo of the signed receipt
  • Context → Proof of delivery
  • Upload

Finally, open the shipment and change status to Delivered. The customer's tracking page shows a green "Delivered" badge and the timeline is complete.

Result — what the customer saw

If Michael opened the tracking page on day 14 he saw:

  • Map with the gold air arc across the Pacific, then truck / van / bike legs in New York
  • His parcel's icon traveling along that route, updating every few seconds
  • Weather at the parcel's current location, plus day/night on the map
  • A timeline with 12 clear events, including the customs inspection note you wrote
  • Photos he could tap to enlarge — pickup, customs form, proof of delivery
  • An ETA that updated itself when the typhoon delay was added
  • Nexora Express logo next to the tracking number — the assigned carrier
This is the whole point of the system. Michael never had to call to ask "where is my parcel?" — everything was visible, in plain English, at every stage.

What this example taught: on a 30-day journey you'll deal with weather, customs, and port delays — sometimes all three. Each has a different behaviour (weather = keep moving, customs = pause, port congestion = keep moving). Getting them right makes the timeline honest.

Validation & popups — how errors surface

Every form on the admin runs its own checks before submitting. You never lose data because a field was empty — the system stops, tells you why, and leaves your work intact.

Three popup colours

ColourMeaningWhat to do
🟢 Green ✓Saved successfully.Nothing. Fades out after 3 seconds.
🟡 Amber ⚠Warning — data saved but check something.Read the message, act if needed, tap to dismiss.
🔴 Red ✕Rejected — nothing was saved.Fix the field named in the message, then resubmit.

Common errors and how to fix them

MessageWhat you typedFix
"Longitude must be negative"New York with positive longitudeUse -74.0060, not 74.0060
"Latitude must be between -90 and 90"You typed 118 (a longitude) in the latitude fieldSwap the values
"Origin and destination cannot be the same"Same coordinates for bothCheck the destination lat/lng
"Logo exceeds 512 KB"A 3 MB photoCompress it (any free compressor works) or use a URL instead
"Pick at least one file"Upload button hit with no fileChoose the file first
"Delay is unrealistically large"Delay value 99999Use weeks or months for long delays instead of a huge minutes value

Downloads

Two files to keep safe — save them together and back them up.

  • Full project archive (ZIP) — every source file. Sits in your phone's Downloads folder as nexora-logistics-full-YYYYMMDD-HHMMSS.zip. To move it to a new phone: copy the ZIP, unzip into ~/vibranthub/, and everything works.
  • Regeneration prompt — nexora-rebuild-prompt.txt in the project root. Paste it into any future AI chat and it understands the whole system, so you never have to explain it from scratch.

How to build the archive again

From Termux:

cd ~/vibranthub
STAMP=$(date +%Y%m%d-%H%M%S)
OUT="$HOME/storage/downloads/nexora-logistics-full-$STAMP.zip"
zip -r "$OUT" . -x "*.bak*" "*before*" "*broken*" "*backup*" "backups/*" "*.zip" -x "storage/cache/*" "storage/logs/*"
ls -lh "$OUT"

The file lands in your Downloads folder. Share it, upload it, keep it as a backup.

How to restore on a fresh phone

cd ~
unzip ~/storage/downloads/nexora-logistics-full-YYYYMMDD-HHMMSS.zip -d vibranthub
cd vibranthub/public
php -S 127.0.0.1:8000

Then open http://127.0.0.1:8000/ in the browser. Everything is where it was.

Do not skip backing up the ZIP. If the phone is lost, wiped, or you switch devices, the ZIP is the entire project. Everything you built is inside it.
