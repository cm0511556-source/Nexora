───────────────────────────────────────────────────────────────
HARD-WON RULES (these are the ones that caused bugs)
───────────────────────────────────────────────────────────────
1. When embedding PHP data into a <script> block, ALWAYS add
   these flags to json_encode:
   JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT |
   JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES
   Otherwise < in the data breaks out and kills the JS parser.

2. Turn OFF display_errors in admin pages:
   @ini_set('display_errors', '0');
   @error_reporting(E_ERROR | E_PARSE);
   Otherwise PHP warnings get written into the HTML/JS.

3. Mapbox fullscreen must be CSS-only (position:fixed + resize),
   NOT the native Fullscreen API. Native API triggers Android's
   "drag to exit" toast and the customer can't see it anyway.

4. Great-circle arcs: when drawing a route from point A to point B,
   compute the SHORT great-circle path in JS, don't use raw DB
   route points (they can go the long way around the globe).

5. Vehicle marker rotation: only rotate ✈️/🚆/🏍️ icons — leave
   🚚/🚐/🚶 upright. Compute bearing from current → next stop.

6. .env values must be wrapped as: APP_NAME="Nexora Logistics"
   Both with double quotes and one line, no spaces around =.

7. Never silently write user-typed data into a JS variable
   without escaping. This is the #1 cause of "Unexpected token".

───────────────────────────────────────────────────────────────
VALIDATION RULES (client-side, before submit)
───────────────────────────────────────────────────────────────
Create shipment:
  - tracking number, name, origin, destination required
  - lat ∈ [-90, 90], lng ∈ [-180, 180]
  - origin ≠ destination
  - if origin contains "Los Angeles/New York/etc." and lng > 0,
    error: "western hemisphere — longitude must be negative"
  - speed ≥ 0
  - email format check

Route editor:
  - name required
  - lat/lng valid
  - waypoint_type in whitelist
  - leg_type in whitelist

Carriers:
  - name required
  - logo ≤ 512 KB and MIME ∈ {png, jpeg, webp, svg}
  - URLs start with http:// or https://
  - email format

Testimonials:
  - name + review required, review ≥ 10 chars
  - rating 1–5
  - photo ≤ 512 KB and MIME ∈ {png, jpeg, webp}

Incidents:
  - incident selected
  - delay_value ≥ 0 and ≤ 100000
  - delay_unit ∈ {minutes, hours, days, weeks, months}

Media upload:
  - at least 1 file
  - MIME whitelist
  - photos ≤ 2 MB, videos ≤ 20 MB

CUSTOMER EXPERIENCE
───────────────────────────────────────────────────────────────
1. Customer lands on homepage → sees hero + tracking form
2. Types tracking number → goes to /track.php
3. First visit: form asks for name/email/phone → saved in DB
4. Then sees:
   - Mapbox satellite map with the shipment's current position
   - Flag pins for origin/destination
   - Route colored per transport mode (gold air, blue sea,
     grey truck, purple van, pink bike, dark pedestrian)
   - Vehicle marker with the correct emoji
   - Day/night terminator shadow over the world
   - Weather HUD (temp, condition, local time)
   - Progress bar (km travelled / remaining / %)
   - Timeline with customer-friendly wording
   - Shipment media strip (public photos + videos)
   - Holds banner (red) if something is wrong
5. Page auto-refreshes every 8 seconds

Admin sees the SAME map + has control buttons.

TONE FOR THE AI
───────────────────────────────────────────────────────────────
- Work one step at a time
- Wait for the user to run each command and paste output
- Never assume a command succeeded
- When a patch fails, inspect the ACTUAL file content
- Prefer str_replace over regex for one-off edits
- Test with php -l before declaring success
- Backup before every destructive change
- The user is on mobile — keep terminal output short
- Never use /tmp — use $TMPDIR on Termux
- Preserve the VibrantHub namespace in app/ (legacy)
